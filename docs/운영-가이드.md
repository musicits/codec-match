# 운영 가이드

기기 추가·배포 방법은 [README](../README.md) 에 있습니다.
이 문서는 **검색엔진·애널리틱스 쪽 남은 작업**을 다룹니다. 순서대로 할 필요 없이 필요할 때 하나씩 하면 됩니다.

## 현재 상태

| 항목 | 상태 |
| --- | --- |
| 구글 서치 콘솔 — `/codec-match/` 속성 | 소유확인 완료 |
| 네이버 서치어드바이저 — `musicits.github.io` | 소유확인 완료 |
| 사이트맵 파일 | 생성됨 (제출은 아직) |
| GA4 추적 코드 | **미설치** |
| GitHub Releases 태그 | 미생성 |

관련 저장소가 두 개입니다. 헷갈리지 마세요.

- **`musicits/codec-match`** → `https://musicits.github.io/codec-match/` (도구 본체)
- **`musicits/musicits.github.io`** → `https://musicits.github.io/` (루트 랜딩 · 네이버 확인 파일 · robots.txt)

## 1. GA4 추적 코드 설치

지금 GA4 속성과 데이터 스트림은 만들어져 있지만 **사이트에 태그가 없어서 방문자가 하나도 잡히지 않습니다.**
서치 콘솔 ↔ GA4 연결도 이 태그가 있어야 의미가 생깁니다.

### 측정 ID 찾기

1. [Google Analytics](https://analytics.google.com) 접속
2. 왼쪽 아래 **관리**(톱니바퀴)
3. **데이터 수집 및 수정 → 데이터 스트림**
4. 웹 스트림(`티거잼 - GA4`) 클릭
5. 오른쪽 위 **측정 ID** — `G-` 로 시작하는 값을 복사

### 설치

측정 ID 를 알려주시면 제가 넣어드립니다. 직접 하실 거면:

`app/index.html` 의 `</head>` 바로 위에 아래를 붙이고 `G-XXXXXXXXXX` 를 실제 ID 로 바꿉니다.

```html
<script async src="https://www.googletagmanager.com/gtag/js?id=G-XXXXXXXXXX"></script>
<script>
  window.dataLayer = window.dataLayer || []
  function gtag(){dataLayer.push(arguments)}
  gtag('js', new Date())
  gtag('config', 'G-XXXXXXXXXX')
</script>
```

그다음 배포합니다.

```bash
cd app && npm run deploy
```

루트에 바뀐 파일을 커밋·푸시하면 반영됩니다.

### 확인

배포 후 사이트를 열고 GA4 → **보고서 → 실시간** 에서 본인이 잡히면 성공입니다. 보통 1분 안에 뜹니다.

> 보관본(`/v1/` ~ `/v6/`)에는 태그가 없습니다. 당시 빌드 그대로라 그게 정상입니다.

## 2. 구글 서치 콘솔 — 사이트맵 제출

소유확인만으로는 색인이 느립니다. 사이트맵을 넣어야 구글이 페이지 목록을 바로 압니다.

1. [Search Console](https://search.google.com/search-console) 에서 속성 `https://musicits.github.io/codec-match/` 선택
2. 왼쪽 메뉴 **Sitemaps**
3. "새 사이트맵 추가" 칸에 **`sitemap.xml`** 입력 (전체 주소 말고 이것만)
4. **제출**

"성공" 으로 바뀌면 끝입니다. 색인까지는 며칠 걸립니다.

### 색인을 더 빨리 원하면

왼쪽 **URL 검사** 에 `https://musicits.github.io/codec-match/` 를 넣고 → **색인 생성 요청**.
하루 몇 건으로 제한되니 중요한 페이지에만 쓰세요.

## 3. 네이버 서치어드바이저 — 사이트맵·수집 요청

네이버는 `https://musicits.github.io` (호스트 루트) 로 등록돼 있습니다.

1. [서치어드바이저](https://searchadvisor.naver.com) → **웹마스터 도구** → 사이트 선택
2. **요청 → 사이트맵 제출** → `sitemap.xml` 입력 → 확인
3. 이어서 **요청 → 웹페이지 수집** → `https://musicits.github.io/codec-match/` 입력 → 확인

`sitemap.xml` 안에 루트와 `/codec-match/` 둘 다 들어 있어서 한 번만 제출하면 됩니다.

### 점검

**검증 → robots.txt** 에서 `https://musicits.github.io/robots.txt` 가 정상으로 읽히는지 확인하세요.
robots.txt 는 **호스트 루트에 있을 때만** 크롤러가 읽습니다. `/codec-match/robots.txt` 는 무시되므로,
새 도구를 추가하면 그 사이트맵도 **루트 저장소의 robots.txt** 에 한 줄 추가해야 합니다.

```
Sitemap: https://musicits.github.io/새도구/sitemap.xml
```

네이버는 색인이 구글보다 느리고 보수적입니다. 등록했다고 바로 검색에 뜨지 않습니다.

## 4. 루트 사이트를 서치 콘솔에 추가 (선택)

지금 서치 콘솔 속성은 `/codec-match/` 하위라서 **robots.txt 보고서와 크롤링 통계가 잠겨 있습니다**
("루트 수준 속성에서만 가능"). 루트를 속성으로 추가하면 열립니다.

1. Search Console → 속성 추가 → **URL 접두어** → `https://musicits.github.io/`
2. 확인 방법에서 **HTML 태그** 선택 → `<meta name="google-site-verification" content="...">` 복사
3. 그 태그를 알려주시면 제가 루트 저장소 `index.html` 의 `<head>` 에 넣겠습니다
   (직접 하실 거면 `musicits.github.io` 저장소의 `index.html` 을 편집)
4. 배포되면(1~2분) 서치 콘솔에서 **확인** 클릭

> **도메인** 방식은 안 됩니다. `github.io` 는 본인 소유 도메인이 아니라 DNS 확인을 할 수 없습니다.
> 반드시 **URL 접두어** 로 하세요.

## 5. GitHub Releases 태그 만들기

버전별 릴리즈 노트는 [CHANGELOG.md](../CHANGELOG.md) 에 커밋 SHA 와 함께 정리돼 있습니다.
그대로 복사해서 쓰면 됩니다.

1. 저장소 → **Releases** → **Draft a new release**
2. **Choose a tag** → `v1.0.0` 입력 → **Create new tag: v1.0.0 on publish**
3. **Target** 을 CHANGELOG 에 적힌 커밋으로 지정
4. 제목과 본문을 CHANGELOG 에서 복사
5. **Publish release**

| 태그 | 커밋 |
| --- | --- |
| v1.0.0 | `643a728` |
| v2.0.0 | `cacafe4` |
| v3.0.0 | `a2ecddf` |
| v4.0.0 | `887cf62` |
| v5.0.0 | `a1d37b2` |
| v6.0.0 | `58e8828` |
| v7.0.0 | `dc05efc` |

기능상 꼭 필요한 작업은 아닙니다. 저장소를 보는 사람에게 이력이 정돈돼 보이는 정도의 이득입니다.

## 6. 검색 유입 늘리기

기술적 세팅은 "검색에 걸릴 수 있는 상태"를 만드는 것까지입니다. 실제 유입은 그다음입니다.

- **블로그에서 사이트로 링크** — 가장 효과가 큽니다. 소개 글을 쓰고 본문에서 링크를 거세요.
  사이트에서 블로그로 가는 링크는 이미 푸터에 있으니, 반대 방향을 채우면 양방향이 되어
  저작 증빙도 서로 보강됩니다.
- **검색어를 염두에 둔 제목** — "갤럭시 버즈3 프로 아이폰 코덱", "LDAC 지원 이어폰" 처럼
  사람들이 실제로 치는 말이 블로그 글 제목에 들어가야 합니다.
- **실적 확인** — 서치 콘솔 → **실적** 에서 어떤 검색어로 노출되는지 2~3주 뒤부터 보입니다.
  거기서 나온 검색어를 사이트 문구에 반영하는 게 다음 단계입니다.

## 새 버전 낼 때 체크리스트

기기만 추가할 때는 [README](../README.md) 절차면 충분합니다. **버전을 올릴 때는** 아래를 같이 맞추세요.

1. `app/src/data/changelog.js` 맨 위에 새 항목 추가 (`phones`/`audio` 는 실제 대수 — 안 맞으면 빌드 실패)
2. `app/index.html` JSON-LD 의 `softwareVersion`, `dateModified` 수정 — **자동 검사가 안 걸립니다**
3. `CHANGELOG.md` 에 같은 내용 추가
4. 직전 버전 보관: `cd app && node scripts/archive-version.mjs v7 <직전 배포 커밋>`
5. 보관한 버전의 changelog 항목에 `archiveUrl: './v7/'` 추가
6. `app/public/sitemap.xml` 의 `lastmod` 를 오늘 날짜로
7. `cd app && npm run deploy` → 커밋·푸시

날짜는 **오늘 날짜**를 쓰세요. 이전 항목 값을 복사하면 틀립니다 (v7 에서 실제로 났던 실수입니다).
